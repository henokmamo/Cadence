Troubleshooting: "there is no CI run at all"

Nine times out of ten this means the .github folder didn't get into your upload — browsers and zip tools love to hide folders that start with a dot.

  1. Go to your repo's Code tab. Do you see a folder named .github? You can also just type .github/workflows/ci.yml in the repo's file-finder box (press t on the Code tab).
  2. If it's missing, add it by hand — takes a minute: Add file → Create new file, then type the path .github/workflows/ci.yml into the filename box (typing the / characters makes GitHub create the folders).
  3. Open ci.yml from your unzipped download in Notepad, select all (Ctrl+A), copy, paste it into the big text box, Commit changes.
  4. That commit will itself trigger the run — go back to Actions.

Also worth a look: Settings → Actions → General should say actions are allowed. On a fresh personal repo they are by default; only tick anything there if your Actions tab is empty and the workflow file definitely exists.

If you see an exit code

GitHub shows failures as Error: Process completed with exit code N. The number is not random — xcodebuild uses the standard Unix sysexits codes. Here's what each one means for you:

CodeMeansWhat you do
74 xcodebuild couldn't read a file — in practice the project file is missing or unparseable. (This is what your first run hit: a real bug in my project generator, fixed — see below.) Check the Code tab: does Cadence.xcodeproj/project.pbxproj exist? If it's missing, re-upload the Cadence.xcodeproj folder. If it's there, the file is likely truncated — re-upload it.
65 The build ran and genuinely failed — real compile errors in the Swift code. This is the good kind of failure: it means everything was found and read. Copy me the error: lines from the log (see step 4 above). I fix, you re-upload, we repeat.
70 The simulator/destination couldn't be resolved (a runtime or device-name mismatch). Paste me the lines above the error — the workflow needs its simulator picker adjusted.
